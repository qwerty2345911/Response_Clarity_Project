## 2. 深度效率分析

### 2.1 本地模型的极致轻量
在传统预训练模型（PLM）中，RoBERTa 展现了最高的推理效率（吞吐量 294 samples/sec，单条延迟仅 3.4 毫秒），且显存占用最低（仅 0.52 GiB）。DeBERTa-v3 由于参数量最大，推理耗时和显存占用均约为 RoBERTa 的两倍。这表明如果仅做本地部署，RoBERTa 是性价比最高的选择。

### 2.2 集成方法的隐性成本
虽然 C 同学采用的是软投票（Soft Voting），不需要额外的训练成本，但在推理阶段，必须同时加载并运行三个模型。这意味着在实际工程中，Soft Voting 的显存占用将是三个模型之和（约 1.94 GiB），推理时间也将累加（预计在 5 秒左右）。考虑到其 Macro-F1（0.2798）甚至低于 RoBERTa 单模型，这种算力开销并未带来应有的回报。

### 2.3 大语言模型（LLM）的维度差距
通过 API 调用 DeepSeek-Flash 虽然免去了本地 GPU 的显存压力，但其延迟极为惊人：
* **LLM-only** 单次推理耗时 1470 秒（单条 4.78 秒）。
* **LLM-assisted** 因为输入的 Prompt 包含了更长的先验信息，推理耗时进一步增加到了 1996 秒（单条 6.48 秒）。
相比于本地 RoBERTa（3.4 毫秒），**LLM 的延迟慢了高达 1400 倍**。

然而，结合分类性能来看：
* RoBERTa（3.4 毫秒）换来 0.2986 的 Macro-F1。
* LLM-assisted（6480 毫秒）换来了 **0.4766** 的 Macro-F1（提升近 60%）。

## 3. 最终结论
在 Response Clarity 这种高度主观、边界模糊的细粒度分类任务中，传统小模型的集成难以打破语义理解的“天花板”。虽然 LLM 的延迟极高，但其带来的性能飞跃是决定性的。从工程落地的角度，我们建议采用**“RoBERTa 快速初筛 + LLM-assisted 疑难复核”**的级联（Cascade）架构，从而在算力成本与分类精度之间取得最佳平衡。
